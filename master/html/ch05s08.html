Following the Vehicles Live

The endpoint /stib/vehicle-trip returns the latest positions as GeoJSON. The table live_vehicles keeps the trajectory of each run, and the function stib_ingest appends the positions of a snapshot to it with the function appendInstant. A snapshot read twice appends nothing, since a position is only appended after the last one of its trajectory. 

DROP TABLE IF EXISTS live_vehicles;
CREATE TABLE live_vehicles (
  vehicle_id text PRIMARY KEY,
  line_id text,
  route_id text,
  trip_id ttext,
  trip tgeompoint
);

CREATE OR REPLACE FUNCTION stib_ingest(snapshot jsonb)
RETURNS integer AS $$
  WITH f AS (
    SELECT f->'properties' AS p,
      ST_Transform(ST_SetSRID(ST_GeomFromGeoJSON(f->'geometry'), 4326), 31370) AS geom
    FROM jsonb_array_elements(snapshot->'features') AS f ),
  n AS (
    SELECT p->>'uuid' AS vehicle_id, p->>'lineId' AS line_id, p->>'routeId' AS route_id,
      to_timestamp((p->>'timestamp')::float) AS t, p->>'tripId' AS trip_id, geom
    FROM f ),
  upsert AS (
    INSERT INTO live_vehicles AS l (vehicle_id, line_id, route_id, trip_id, trip)
    SELECT vehicle_id, line_id, route_id, ttext(trip_id, t), tgeompoint(geom, t)
    FROM n
    ON CONFLICT (vehicle_id) DO UPDATE
    SET trip = appendInstant(l.trip, EXCLUDED.trip),
      trip_id = CASE
        WHEN EXCLUDED.trip_id IS NULL THEN l.trip_id
        WHEN l.trip_id IS NULL THEN EXCLUDED.trip_id
        ELSE appendInstant(l.trip_id, EXCLUDED.trip_id) END
    WHERE getTimestamp(EXCLUDED.trip) > endTimestamp(l.trip)
    RETURNING 1 )
  SELECT count(*)::integer FROM upsert;
$$ LANGUAGE sql;

The following script polls the endpoint every 20 seconds and passes each snapshot to the function. The command \set of psql reads the snapshot into a variable, which a command-line argument could not hold. 

#!/bin/bash
# Poll the STIB vehicle positions of MobilityTwin.Brussels every 20 seconds
# and append them to the trajectories of table live_vehicles.
# Usage: MOBILITYTWIN_TOKEN=... ./stib_live.sh [database]
DB=${1:-stib}
URL=https://api.mobilitytwin.brussels/stib/vehicle-trip
while true; do
  if curl -sf -H "Authorization: Bearer $MOBILITYTWIN_TOKEN" "$URL" -o snapshot.json; then
    psql -X -q -At -d "$DB" <<'EOF'
\set s `cat snapshot.json`
SELECT now()::time(0) AS polled, stib_ingest(:'s') AS appended;
EOF
  fi
  sleep 20
done

Each line printed is a poll and the number of runs whose trajectory grew. While the script runs, the vehicles that have been standing still for at least 3 minutes away from any stop are obtained as follows. 

SELECT l.line_id, l.vehicle_id, duration(s)::interval(0) AS stopped_for,
  ST_AsText(ST_Transform(endValue(s), 4326)) AS position
FROM live_vehicles l,
  unnest(sequences(stops(atTime(l.trip, span(now() - interval '15 minutes', now())),
    20.0, interval '3 minutes'))) AS s
WHERE tempSubType(l.trip) <> 'Instant'
  AND startTimestamp(s) > startTimestamp(l.trip)
  AND endTimestamp(s) = endTimestamp(l.trip)
  AND NOT EXISTS (SELECT 1 FROM stops p
    WHERE ST_DWithin(p.stop_geom, endValue(s), 50.0));

The function atTime keeps the last 15 minutes of each trajectory, and a vehicle is still standing when its last stop ends with its trajectory. As for the day of service, a stop starting with the trajectory is left out: the vehicle has not moved since the script started, which is how a layover looks.
